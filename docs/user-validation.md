# User validation

**Status: real user demand is NOT yet validated.** No external user has tried the product as of
2026-10-23. Everything below that is measured uses synthetic data created for this repository.

## What exists as evidence of the problem (secondary sources, not our users)

- Shopify documents CSV product import, templates and common import errors, so the workflow exists.
- Commercial importers (e.g. CSVbox, Flatfile) sell column mapping, validation and transformation;
  AI-assisted mapping is not unique to this project.
- None of this shows that CatalogBridge has users, a market, or willingness to pay.

## Planned real-user test (author-run; nobody is contacted automatically)

Goal: 3 people who prepare product catalogs from several suppliers (small e-commerce operators or
people who help merchants list products). Ideally each brings a de-identified real CSV.

Script (about 20 minutes each):

1. Ask about their last catalog cleanup: steps, time spent, common problems, current tools.
2. Same task twice: their usual method vs CatalogBridge, on their file or a provided one with
   different column names.
3. Record: task time each way, number of mapping edits, time to fix errors, whether the output
   file was usable as-is, and whether they would use it again (and why not).
4. Ask what is missing or confusing.

## Without recruiting: two substitutes (labelled as such)

Neither of these is user validation. They test behaviour on real-world formats and give the
author's own before/after timing.

### A. Public real-world sample files

`scripts/public_data_check.py` runs official sample product files from e-commerce platforms
through the deployed stack (files are downloaded at run time, not committed; SHA-256 recorded).
Results: `docs/evidence/public-data-*.json` and the section "Public data results" below.

### B. Author self-test (dogfooding), one task, two methods

File: `fixtures/self_test_supplier_b.csv` (40 rows, unfamiliar headers 倉位/貨號/品名/單價/現貨/單位,
currency TWD). It contains a few planted problems; **do not open the generator code before the test**.

Task: produce a clean product list with columns `sku,title,price,currency,stock` (price with
2 decimals, currency TWD) **and** a list of the rows that cannot be used with the reason.

1. **Manual first** (Excel/Numbers/Google Sheets, any method you would really use). Start a timer
   when you open the file; stop when you have both the clean list and the problem list.
2. **Then CatalogBridge**: New job (currency TWD) → map → run → download output and error report.
   Time from choosing the file to having both downloads.
3. Compare your manual problem list with the error report. Count problems each method found.

## Public data results (2026-10-28)

Raw: `docs/evidence/public-data-20261028T020925.json`. Run through the deployed stack with the
current rules (rules.v2). Answer keys were written by hand from the column meanings.

| File | Source / license | Rows × columns | AI mapping (4 fields) | Run result |
| --- | --- | --- | --- | --- |
| WooCommerce `sample_products.csv` | woocommerce/woocommerce, GPL-2.0 | 25 × 51 | 4/4 (price ← `Regular price`, not `Sale price`) | 22 valid / 3 invalid |
| Magento `products_gear_bags.csv` | magento/magento2-sample-data, OSL-3.0 | 14 × 19 | 4/4 (stock ← `qty`) | 14 valid / 0 invalid |

Not obtained: Shopify `product_template.csv` (HTTP 403, bot protection, not bypassed); Open Food
Facts search export (HTTP 503 twice).

What this exposed:

1. **Stock required (rules.v1) rejected the whole WooCommerce file** (0/25 offline): the sample leaves
   `Stock` empty for every product because stock is not tracked. The author decided to make stock
   optional (decisions D20); with rules.v2 the file gives 22/25.
2. The 3 remaining invalid rows are a `variable` and a `grouped` parent product with no own price
   (rows 1, 2, 23): correctly rejected.
3. **Variants are flattened:** 7 `variation` rows pass as independent products and lose the link to
   their parent. Product variants are out of scope (spec §4.3); this is now listed as a known limit.
4. AI suggestions picked the right 4 columns out of 51 and 19 on these real headers (2 files only).
